# Candidate conformance vectors

All seeds, names, UIDs and keys here are invented or published test data.
Never use these seeds or their descendants for an installation.

Run negatives first, then the positive controls. `refusals.json` contains
71 stable refusal IDs and 71 explicitly paired controls. Each pair differs
at exactly one input field (`mutation_path`, a JSON pointer). Frame tests
change a single `frame_hex` field containing complete wire bytes; they do not
pretend a protocol packet is one semantic member. Array-valued fields count
as one field. All refusals require no signature/private material returned and
no binding/enrollment mutations, apart from permitted bounded audit writes.

| File | Coverage |
| --- | --- |
| `refusals.json` | Foreign peer, inactive/reused generations, unavailable source, open-connection revoke/retire races at release and next request, hardened paths and purposes, SSHSIG restrictions and rejected agent mutations, concrete native malformed frames, operator register/revoke authority, mandatory registrar-array uid_map and pinned enrollment, revoked/missing helper binding, executable-qualified refusal, registrar name bounds, domain separation, private-material request rejection and audit failure |
| `slip0010-ed25519.json` | Public SLIP-0010 Ed25519 test vectors 1 and 2: all six nodes each, expected chain code and SLIP-encoded public key; source URL and source SHA-256 retained |
| `authority-root.json`, `authority-root/` | G4 draft: 84 byte goldens, 46 adjacent negative/positive pairs and 31 preimage links; integrity and hold-origin domain check, full PC2 reader/runtime qualification PENDING |
| `keymaker-paths.json` | Fixed public 32-byte seed, explicit scoped registry and five name → path → Ed25519/SSH public-key examples; purpose and ancestor separation |

`evaluation` names the future harness layer. Binding checks may directly
inject a candidate binding to exercise UID equality; a real daemon must also
select its binding by authenticated peer. `peer_uid`, journal states,
connection phase and operator-verifier verdicts are trusted **harness inputs**,
never native request members. These fixtures are candidate policy expectations,
not a service implementation. The `operator_record` fixture is an interface
stand-in, not a published signed-act format.

Helper `enrollment` inputs are harness views of a validated snapshot, with
availability/verifier facts alongside the registrar-shaped `uid_map` array and
names policy. They are not enrollment envelopes. Binding status is a separate
local fact. Wrong, undeterminable and matching executable snapshots each pair
an exe-qualified row (refused `enrollment_unsupported`) with a UID-only row
that can sign. The single changed field is the array, treated as one input
field; executable evidence is unchanged within each pair. No positive control
claims that a procfs path comparison qualifies executable enforcement.

`before_release` means revoke/retire is committed before the request's final
release fence. `next_request` means the same accepted connection sends again
after that change. A future concurrency test must enforce these orderings;
merely changing a static fixture state does not prove a real race is closed.
Private-material vectors reject requests for extra output members. Future
service tests must also inspect every normal and error response/log to prove
the output invariant without relying on a malicious client asking for secrets.

`expected_wire_hex` is the SSH agent failure packet. Rich refusal codes go
into audit, not a nonstandard SSH reply. Native errors carry their code in
the response error object. Oversize tests provide only an over-cap header;
truncation tests close the input at EOF, rather than relying on a timeout.

## Reproduction

From the repository root:

```sh
go run ./tools/vectors/main.go -check
go run ./tools/vectors/main.go -write
```

`-check` verifies the independent published controls, every documented refusal
code and one-field pairing, and exact regeneration of path examples. It does
not evaluate refusal policy or sign a service response. `-write` first checks
the published controls and pair structure, then rewrites only path expectations;
review that diff. Expected published results are never regenerated by the tool.
The offline program needs no dependency downloads and creates no repository
build artifacts. Go's normal external build cache may be used.

Published controls are taken from
[SLIP-0010's Ed25519 vectors](https://github.com/satoshilabs/slips/blob/master/slip-0010.md).
The prefixed public encoding is `00 || public_key`; the key itself has 32
bytes. The fixture intentionally omits published private-node values: the
generator compares independently published public keys and chain codes.
The SSH packet format follows the
[SSH agent draft](https://www.ietf.org/archive/id/draft-miller-ssh-agent-17.txt)
and [OpenSSH SSHSIG signed-data layout](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.sshsig).

## S4 publication adoption fixtures

[waggle-s4](waggle-s4/README.md) retains the exact public pinned
P-JRN-publish-reissue fixture and six negatives, with byte hashes and MS-S row
mapping. These imports are separate from the 71 native refusal/control pairs.
The existing vectors tool does not execute them or evaluate verifier policy;
byte/provenance checks are documentation validation. Consumer execution and
MS-S13–MS-S22 remain PENDING in the message-state spec.

## Combined authority-root draft fixtures

The [G4 draft](../spec/keymaker-authority-root.md) is content for architect,
reviewer and curator acceptance before PC2 S1 code. `authority-root.json` lists
84 canonical JSON goldens and 46 named adjacent negative/control groups. Each
group carries its own claim. Inputs, UIDs, inode metadata, provider digests and
verity measurements are **invented harness inputs**, not an installed policy,
valid signed provider document, measured file or independent custody proof.
A format control grants no eligibility: the minimal root has no entries and
custody_ready=false; the maximal root contains withdrawn history.

The goldens include untagged legacy, closed schema 2 and combined schema 3
snapshots, private payload, minimal and 255-byte-text roots, an exactly 1048576-byte
root with 1300 sorted entries, seven migration records (all six phases and
existing-schema-2 entry), attempt/hold and domain preimages. The maximal root is
losslessly gzip-compressed; its expected decompressed SHA256/length are in the
manifest. Expansion is bounded in the checker. Source JSON bytes have no newline.

Thirty-one links pin root/binding/facts/participants/candidate/attempt/hold hashes,
including populated freshness-payload/root and freshness-policy preimages. The
checker materializes each negative mutation, checks its exact SHA256/length and
unchanged positive-control selection, then checks that control's declaration. It
additionally checks every hold golden's origin link against its kind-specific A2
preimage domain/member set and executes the authority-hold-origin-domain
negative with its adjacent valid control. It does **not** implement full reader
rejection, active append, recovery, fs-verity, cross-process exclusion, current
restore custody or latency. All such verdicts remain PENDING. expected_rejection values are fixture categories,
not new public refusal codes. Changing a rejection label cannot establish a runtime
claim; later consumer tests must actually decode/refuse each named input before
reporting a kill. Unknown/duplicate/alias, other domain, truncation, field/total size,
floor/old-root, provenance read-set and aggregate-reservation pairs remain
executable fixture-integrity checks only.

Seventeen additional goldens cover the single combined codec's empty/retained
message authority, eight-field genesis/positive anchors, normal freshness and
same-head reanchor artifacts (two skipped positions and zero), exact journal
prior reference, normal/recovery policy and a populated payload/root/preimage
chain. Their external signed-input references are invented format inputs, just
like participant measurements; they are not signed-producer accepts or receipts.
Ten new negative/control pairs cover receipt persistence, missing inventory,
positive-anchor null ID, missing/oversized independent prior, W rollback, skip
count, boolean audit substitution, missing endpoint and wrong artifact domain.
Actual signed S4/S5 verification remains a separate consumer qualification gate.

Rework 1 adds 27 goldens and 14 pairs for the zero-checkpoint/genesis domain,
positive seq-1 controls, zero/nonzero-hash mismatch, rollback/reset, missing
independent genesis, positive activation tails, and the C0/Q0/M0/Q1/R0 capacity
bootstrap DAG. The seq-1 hash uses the already-imported public gen-journal
creating.jsonl line including LF; no journal activity is fabricated or appended.
All zero-checkpoint root/provenance/facts/link/floor/recovery copies agree.

Raw byte-span mutations preserve negative zero, fraction/exponent spelling,
max-safe-integer+1, depth17, invalid UTF-8 and decoded duplicate member names.
Nearby controls use zero/one/max-safe integers, depth16 and valid literal U+00E9.
The closed depth/UTF8 wrapper is a fixture-only generic CCJ context; it is not
accepted as a Root. Genesis-authority references and capacity/provider metadata
remain invented external fixture inputs, not actual independent admission or
capacity/verity qualification. C0 alone is never serving authority. Full reader
rejections remain PENDING; the tool checks exact planted bytes and pair hashes.

Rework 2 adds exact journal-genesis-candidate and journal-genesis-transaction
preimages. The authority hold's origin is the latter's A2 transaction ID, with
base_root_digest=null and the zero-journal root's revision and candidate. Only
that hold and the recovery record retaining its digest change among earlier
goldens. The new authority-hold-origin-domain pair substitutes the C0 digest and
is rejected by the offline domain predicate; the transaction-origin control
passes. Every authority-kind hold must link to keymaker-authority-tx/1, every
activation-kind hold to the immutable pc2-activation-attempt/1 identity preimage,
excluding attempt_id, disposition and evidence_digest. This bounded check does
not admit a real attempt/transaction or resolve unknown outcomes. C0-specific
recovery semantics remain the G5-E owner gate.

Run `go run ./tools/vectors/main.go -check` from the repository root. `-write`
still rewrites **only** keymaker-paths.json; it must not regenerate golden expected
PC2 hashes. No daemon or service-state file is read by this tool.
