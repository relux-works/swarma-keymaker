# Candidate conformance vectors

All seeds, names, UIDs and keys here are invented or published test data.
Never use these seeds or their descendants for an installation.

Run negatives first, then the positive controls. `refusals.json` contains
63 stable refusal IDs and 63 explicitly paired controls. Each pair differs
at exactly one input field (`mutation_path`, a JSON pointer). Frame tests
change a single `frame_hex` field containing complete wire bytes; they do not
pretend a protocol packet is one semantic member. Array-valued fields count
as one field. All refusals require no signature/private material returned and
no binding/enrollment mutations, apart from permitted bounded audit writes.

| File | Coverage |
| --- | --- |
| `refusals.json` | Foreign peer, inactive/reused generations, unavailable source, open-connection revoke/retire races at release and next request, hardened paths and purposes, SSHSIG restrictions and rejected agent mutations, concrete native malformed frames, operator register/revoke authority, mandatory uid_map and pinned enrollment, domain separation, private-material request rejection and audit failure |
| `slip0010-ed25519.json` | Public SLIP-0010 Ed25519 test vectors 1 and 2: all six nodes each, expected chain code and SLIP-encoded public key; source URL and source SHA-256 retained |
| `keymaker-paths.json` | Fixed public 32-byte seed, explicit scoped registry and five name → path → Ed25519/SSH public-key examples; purpose and ancestor separation |

`evaluation` names the future harness layer. Binding checks may directly
inject a candidate binding to exercise UID equality; a real daemon must also
select its binding by authenticated peer. `peer_uid`, journal states,
connection phase and operator-verifier verdicts are trusted **harness inputs**,
never native request members. These fixtures are candidate policy expectations,
not a service implementation. The `operator_record` fixture is an interface
stand-in, not a published signed-act format.

`before_release` means revoke/retire is committed before the request's final
release fence. `next_request` means the same accepted connection sends again
after that change. A future concurrency test must enforce these orderings;
merely changing a static fixture state does not prove a real race is closed.
Private-material vectors reject requests for extra output members. Future
service tests must also inspect every normal and error response/log to prove
the output invariant without relying on a malicious client asking for secrets.

`expected_wire_hex` is the SSH agent failure packet. Rich refusal codes go
into audit, not a nonstandard SSH reply. Native errors carry their code in
the response error object. Oversize tests provide only an over-cap header;
truncation tests close the input at EOF, rather than relying on a timeout.

## Reproduction

From the repository root:

```sh
go run ./tools/vectors/main.go -check
go run ./tools/vectors/main.go -write
```

`-check` verifies the independent published controls, every documented refusal
code and one-field pairing, and exact regeneration of path examples. It does
not evaluate refusal policy or sign a service response. `-write` first checks
the published controls and pair structure, then rewrites only path expectations;
review that diff. Expected published results are never regenerated by the tool.
The offline program needs no dependency downloads and creates no repository
build artifacts. Go's normal external build cache may be used.

Published controls are taken from
[SLIP-0010's Ed25519 vectors](https://github.com/satoshilabs/slips/blob/master/slip-0010.md).
The prefixed public encoding is `00 || public_key`; the key itself has 32
bytes. The fixture intentionally omits published private-node values: the
generator compares independently published public keys and chain codes.
The SSH packet format follows the
[SSH agent draft](https://www.ietf.org/archive/id/draft-miller-ssh-agent-17.txt)
and [OpenSSH SSHSIG signed-data layout](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.sshsig).
