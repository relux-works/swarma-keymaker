# Runtime and operator boundaries

Use this reference to explain readiness and route operator work, not to enroll an agent or handle its keys. The public `stationcaller` package is separate from `internal/control`, `internal/keymaker`, `internal/enrollment` and `internal/registration`; Go's internal packages are implementation seams.

## Shipped command and readiness

The [CLI](../../../../cmd/keymaker/main.go) implements `keymaker version`, `keymaker serve --config <file>` and `keymaker enrollment reconcile --config <file> [--bootstrap] [--confirm <sha256>]`. Version prints `0.1.0`; malformed usage returns 2 and serving/reconciliation failures return 1. These names describe the interface, not permission to start it. Configuration parsing alone does not establish installed protection or readiness.

The [protected configuration contract](../../../../packaging/README.md) defines service/operator IDs, paths, epoch and registry pins, optional helper configuration, time policy and generation journal. Use operator-supplied protected inputs; the example's zero IDs and replacement strings are placeholders. The [production entry point](../../../../internal/keymaker/runtime_linux.go) requires an unprivileged service, protected config and matching service identity, trusted time, protected state/master/registry and verified generation evidence before announcing readiness. No static UID lookup or fixture flag substitutes for authority.

Without `generation_journal`, production refuses `generation_source_unavailable`. Its `path` and `initial_floor: {seq, hash}` use the user-manager-owned `gen-journal/1` contract. The floor applies only to pristine local state with no prior anchor or binding issuance. A lost/corrupt established anchor, rollback/fork, stale writer or reserve incident fences with nonretryable `generation_source_fenced`; retain incident evidence for operator reconciliation, not automatic reinitialization. See [generation authority](../../../../spec/keymaker.md#31-peer-identity-and-generation-source) and the [adapter](../../../../internal/keymaker/generation_anchor_linux.go). A real root-owned journal and its release/retirement ordering still need activation qualification; late-recorded retirement is not fenced.

## Enrollment and revocation

The [enrollment contract](../../../../internal/enrollment/README.md#operator-reconciliation-procedure) belongs to a stopped helper/daemon and a privileged operator. First acceptance requires explicit bootstrap of a directory with no prior entries; every later restart needs fresh operator reconciliation against independently trusted history. Protected pins include the exact Git object format/revision, maintainers, publisher, audience, registry, service UID and generation policy. Readable local state or a locally computed digest does not establish freshness.

Keep command names and their meaning distinct from agent instructions: `enrollment reconcile` confirms a full state digest and publishes a one-use approval; `--bootstrap` is initial acceptance, not repair. Failed/partial state, consumed approvals and publication fences are recovery evidence. Keep the helper stopped on mismatch or interrupted-write fences, retain reports and route separate privileged recovery. Do not delete markers, edit high-water/approval files, restore consumed consent or bootstrap over prior evidence. A Commit error poisons that Authority instance and needs startup with independent reconciliation; another live reload cannot repair it.

The current [registration-helper wiring](../../../../internal/keymaker/runtime_linux.go) invokes `configureRegistration`; its [implementation](../../../../internal/keymaker/registration_linux.go) and [registration contract](../../../../internal/registration/README.md) govern purpose-2 registrar proofs and final authority checks. This is distinct from station-caller purpose 6. Missing/untrusted enrollment and unsupported executable-qualified rows refuse; do not fall back to UID-only matching or turn signing/key custody into agent steps.

That wiring explicitly selects the [legacy challenge reconciler](../../../../internal/enrollment/reconcile.go) with `registration_helper.approval_file`. Its startup challenge approval is incompatible with the command records used by the default `New(configPath, nil, nil)` enrollment policy. Do not assume `enrollment reconcile` output un-fences this daemon helper. SIGHUP retries validation with the same startup challenge; it cannot grant authority without the protected decision and complete verification.

Persistent revoke remains `operator_record_unavailable` until signed-act integration and qualified fact sources exist. A positive injected verifier fixture is not runtime authority; production passes no operator verifier. Persistent identities cannot use ephemeral mode (`persistent_revoke_requires_operator`). See [operations and authority](../../../../spec/keymaker.md#5-operations-and-authority) and [native refusal handling](../../../../internal/keymaker/native.go). Account removal and key revocation are separate transactions.

## What fixture checks establish

The [Linux testing guide](../../../../docs/linux-testing.md) describes private single-UID sockets, public fixture seeds and real OpenSSH/Git clients. Injected generation/act authority proves those fixture paths, not root journal ownership, cross-process retirement, deployment sandboxing or production trust. Its older blanket unavailable-generation/deferred-helper statements describe the integration base; current wiring above is narrower and newer.

The separate [multi-UID runner](../../../../cmd/keymaker-window/main.go) needs the owner's pre-provisioned accounts, group, readable configuration and noninteractive permissions. Its direct statuses are 0 pass, 1 failure, 2 malformed usage/configuration and 3 PENDING, with `PENDING: test window not provisioned` on stderr when absent. Make can map failure/PENDING to 2; compilation is not live qualification. Do not provision or run that window as a workaround for unavailable authority.

Witness option C, Swarm Signer, provision/confirm, PC2 serving/migration and native macOS remain behind their [module-owned gates](../../../../UNRESOLVED_QUESTIONS.md). Offline builds, fixture successes and this skill confer no installation, activation or owner authorization. Preserve any source-custodian or owner-sitting hold on the requested operation.
